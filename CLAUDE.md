## Команды

```bash
npm run dev                      # Vite, разработка: localhost:5173/podnebesnaya/ (корень перебрасывает туда)
npm test                         # vitest run — весь набор
npx vitest run src/domain/round.test.ts        # один файл
npx vitest run -t 'название теста'             # один тест по имени
npx vitest                       # режим наблюдения
npm run lint                     # eslint .
npm run build                    # три валидатора → tsc -b → vite build
```

`npm run build` — это и есть полная проверка контента: `validate:map`, `validate:content` и `validate:fonts` идут **до** компиляции, и сборка падает на несогласованных данных раньше, чем на типах. Валидаторы можно гонять по одному (`npm run validate:map`).

## Генераторы: часть файлов нельзя править руками

| Команда | Что делает |
| --- | --- |
| `npm run generate:palette` | перезаписывает `src/map/region-palette.ts` целиком по геометрии SVG; сторожится отпечатком контуров |
| `npm run generate:callouts` | правит `public/maps/china-provinces.svg` на месте — выноски для Макао и Гонконга |
| `npm run generate:hit-targets` | правит тот же SVG — невидимые цели нажатия для регионов мельче порога WCAG |
| `npm run generate:fonts` | пересобирает подмножества шрифтов в `src/assets/fonts` и `scripts/font-coverage.json`; нужен `pyftsubset` с woff2 (`pipx install fonttools && pipx inject fonttools brotli`) |
| `npm run extract:physical` | перезаписывает `scripts/data/physical-source.json` — выжимку из Natural Earth; нужна сеть, в сборку не входит |
| `npm run extract:canal` | перезаписывает `scripts/data/canal-source.json` — линию Великого канала из OpenStreetMap (ODbL, отдельный файл); нужна сеть, в сборку не входит |
| `npm run fetch:photos` | скачивает снимки коллекций с Викисклада в `public/photos`, переписывает `src/content/photo-credits.ts` и `docs/sources/photos.md`; нужна сеть, в сборку не входит |
| `npm run generate:physical` | перезаписывает `src/map/physical-geometry.ts` целиком по выжимке Natural Earth |

Оба SVG-генератора идемпотентны, их блоки ограничены комментариями-метками. Перед правкой любого файла в `src/map/` или самого SVG прочитайте шапку файла: сгенерированные помечены явно.

**Шрифты режутся у нас, а не на стороне Google.** Раньше подмножество приходило по параметру `text=`; с 2026-08-29 для китайских шрифтов это перестало работать — запрос на два иероглифа возвращает весь шрифт (6,15 МБ), а `unicode-range` в ответе по-прежнему повторяет запрошенное. Проверка покрытия такой подмены не видит: полный шрифт покрывает всё. Поэтому `generate:fonts` скачивает то, что отдают, и режет сам через `pyftsubset`, а покрытие считает по вырезанному.

**Новый иероглиф в контенте ломает сборку.** Шрифты подмножествованы; `validate:fonts` сравнивает знаки, встречающиеся в `src`, с покрытием подмножеств. Добавили регион с незнакомым иероглифом — запустите `npm run generate:fonts`, иначе сборка падает (это лучше, чем квадратик в браузере).

## Архитектура

**Роутера нет.** `src/App.tsx` — конечный автомат экранов (`Screen`) и единственное место навигации: он держит весь прогресс, состояние раунда и решает, показывать ли шапку. Новый экран добавляется здесь, а не отдельным маршрутом.

- Шапка (`SiteHeader`) закреплена и стоит на всех поверхностях — её рисует `AppFrame`, а не каждый экран. Высоту кадра под ней считает `.app-frame`, поэтому оболочки внутри о шапке ничего не знают. Карта раунда стоит справа от колонки вопроса (`RoundStage`) и при кадре 1440×900 получает 1066×823: 69 px высоты забирает шапка, около 375 px ширины — колонка.
- `AppFrame fillsFrame` — поверхность занимает экран и не прокручивается. Признак ставится у каждого возврата отдельно, намеренно, а не списком экранов.

**Слои и их границы:**

| Каталог | Правило |
| --- | --- |
| `src/content` | справочники регионов, городов, физических объектов, достопримечательностей, династий, коллекций и источников; чистые TS-модули, валидируются на сборке |
| `src/domain` | чистые функции: раунды, оценивание, прогресс. Не знает ни React, ни DOM |
| `src/features` | поверхности: `home`, `atlas`, `collections`, `exercise`, `results` |
| `src/map` | SVG, фокус, масштаб, сопоставление областей с `regionId` |
| `src/ui` | общая обвязка сайта |
| `src/design` | разбор токенов и пороги контраста (чистый код; чтение с диска — в `scripts/`) |

Границы, которые легко нарушить незаметно:

- **Домен не вызывает `Math.random`.** Генератор передаётся снаружи (`createSeededRandom`, mulberry32) — иначе раунды перестают воспроизводиться в тестах. Сид создаётся в `App.tsx`.
- **Компоненты не трогают localStorage.** Только через `createProgressStore` (`src/domain/progress-storage.ts`).
- **UI не знает ключей SVG, карта не считает правильность ответа.**
- **Пул раунда — не справочник.** Пул отвечает за то, что спрашивают, и на
  «Повторить ошибки» сужается до ошибочных целей. Отвлекающие варианты и
  карта берут справочник целиком: иначе повтор одной ошибки даёт один
  вариант — сам ответ, а области вне пула остаются без русских имён. Справочник
  берётся модульным импортом рядом с пулом-свойством.

**Прогресс вычисляется, а не читается.** `masteredRegionIds` и `unlockedLevel` сохраняются в хранилище (этого требует `DATA_MODEL.md`), но на каждом `commitAttempts` пересчитываются заново из истории попыток — отставшее поле не должно запереть ученика.

**Хранилище деградирует, а не падает.** Доступ обёрнут в try (политика браузера может запретить `localStorage`), запись проверяется пробной записью, а испорченные данные не удаляются — они переносятся в `BACKUP_KEY`, чтобы неудачная миграция ничего не уничтожила. Флаг `store.isAvailable` доходит до экранов итогов: ученика предупреждают, что прогресс не сохранится.

**Скучившиеся цели собираются в гроздь.** `src/map/cluster.ts` — чистые функции: объекты ближе диаметра цели нажатия сходятся в одну цель с числом. Дальше два поведения (решение владельца от 2026-08-30): гроздь **городов** по нажатию по-настоящему приближает карту — `cluster.scale` говорит, во сколько раз, ступень выбирает `ChinaMap`, а `validate:map` роняет сборку на грозди теснее последней ступени. Это **заход на один вопрос**: собственный вид ученика (`zoom` свойством, середина в состоянии) не переписывается, заход живёт отдельным состоянием с ключом `questionKey`, и со сменой ключа перестаёт быть нынешним — возврат вычисляется на отрисовке, а не эффектом (эффекты слоя идут раньше эффектов карты, и приближение к новой грозди уехало бы вместе со старым заходом). Гроздь **достопримечательностей** сама является целью ответа: попадание в неё при спрошенном члене верно, а соседи по грозди (`colocatedLandmarkIds`) исключаются из вариантов «что здесь отмечено». Озёра и крайние точки остались на прежнем разведении целей (`spreadHitTargets`), и это закреплено тестами.

**Карта.** `public/maps/china-provinces.svg` — единственный источник геометрии, попадает в бандл через `import ... from '...svg?raw'`, то есть на сборке, а не запросом. Размер цели нажатия меряется диаметром наибольшей вписанной окружности, а не габаритом контура: у Ганьсу габарит огромный, а сама область — узкий коридор.

**Токены.** `src/design/tokens.css` — единственный источник цветов, размеров и длительностей; компоненты не пишут значения напрямую. `scripts/validate-tokens.test.ts` разбирает тот же файл и проверяет по WCAG 2.2 каждую пару, реально встречающуюся на экране, — палитру нельзя ухудшить незаметно, тест упадёт.

## Хуки: ворота ревью перед сливом в master

`.claude/settings.json` — единственный файл в `.claude/`, который ведётся в
git (остальное скрыто `.claude/*`). В нём два хука:

| Хук | Когда | Что делает |
| --- | --- | --- |
| `PostToolUse` на `ReportFindings` | конец `/code-review` | пишет sha HEAD, ветку, число находок и уровень в журнал |
| `PreToolUse` на `Bash` | каждая команда | если команда сливает в master ветку без записи — отказ с объяснением |

Журнал — `review-log.json` в общем каталоге git (`git rev-parse
--git-common-dir`), один на основной каталог и все рабочие деревья: ревью
делается в ветке, слив — в основном каталоге.

**Ворота открывает факт ревью, а не его итог.** Ревью с находками — тоже
ревью. Исправили находки — sha сменился, нужен короткий повторный прогон.

**Отказ — не запрет.** Хук видит только команды, которые запускает агент;
слив, набранный в терминале руками, проходит. Экстренное исправление по
решению владельца (`AGENTS.md`) этим и делается.

**Известное ограничение (решение владельца от 2026-09-08).** Запись ставится
на текущий HEAD при любом завершённом ревью, в том числе когда `/code-review`
звали с чужой целью — с номером пул-реквеста или другой веткой. Отревьюили
чужое, сидя на своей ветке, — своя помечена просмотренной. Закрыть это можно
было только чтением стенограммы сессии, то есть повесив заслон на внутренний
формат, которого нам никто не обещал. Довод в пользу «оставить»: заслон
напоминает, а не запирает, и обойти его слитием руками и так можно.

Разбор командной строки живёт в `scripts/hooks/merge-command.ts` и не знает ни
про git, ни про файлы — потому и проверяется таблицей входов и выходов.
Скрипты запускает `node` напрямую: Node снимает типы сам, и это втрое дешевле
`tsx` на каждой команде Bash. Из-за `node` соседние модули импортируются **с
расширением** `.ts` — в отличие от прочих файлов в `scripts/`. Перед Node
стоит шелл-отсев `review-gate.sh`: команда без слова `merge` стоит 9,6 мс
вместо 173.

## Что помнить при изменениях

- Интерфейс, задания и ошибки — по-русски; китайские названия в Unicode, не только пиньинем.
- Во время раунда сетевых запросов нет: приложение работает после первоначальной загрузки.
- Существенное решение фиксируется в `DECISIONS.md`, изменение — в `CHANGELOG.md`.
